# 🔍 Dual Index System: Framework + Server

**The ultimate power combo for bytecode patch generation**

---

## 🎯 What This Is

You now have **TWO separate code indexes** working together:

1. **Framework Index** (`code_index.json`) - Your WurmModLoader codebase
2. **Server Index** (`wurm_server_index.json`) - Decompiled Wurm server JAR

**Combined, they let you:**
- Find patch targets in server code
- See existing hooks in framework
- Generate bulk bytecode patches with Qwen
- Understand how framework hooks into server

## 📊 The Two Indexes

### 1. Framework Index (code_index.json)

**What it contains:**
- WurmModLoader framework code
- All your mods

- API definitions

**Generated by:**

### 2. Server Index (wurm_server_index.json)

**Generated by:**
```bash
python3 index_wurm_server.py
```

**Use for:**
- Finding methods to patch
- Understanding server behavior
- Bulk patch generation

## 🚀 Combined Query Tool

**File:** `combined_index_query.py`

### Commands

#### 1. Search Both Indexes
```bash
python3 combined_index_query.py search "getCombatRating"
```

Shows matches in both framework AND server code.

**Example output:**
```

--------------------------------------------------------------------------------
1. public float getCombatRating(...)
   📁 CombatHandler.java
   🏷️  combat, hook
   📝 Gets combat rating for a creature

🎮 WURM SERVER (Decompiled)
--------------------------------------------------------------------------------
1. public float getCombatRating(byte weaponType, boolean defending)
   📁 Creature.java
   📝 Returns combat rating based on skills and weapon
```

**Use case:** Finding both the patch target (server) and existing hooks (framework)

---

#### 2. Pattern Search
```bash
python3 combined_index_query.py pattern bytecode_patches
```

Shows all bytecode patches in framework and any patterns in server.


Shows results from both indexes side-by-side with counts.

## 💡 Typical Workflows

### Workflow 1: Create New Bytecode Patch

**Goal:** Patch server's `getCombatRating()` method

```bash
# Step 1: Find the server method
python3 combined_index_query.py search "getCombatRating"

# Shows you:
# - Server method signature (what to patch)
# - Framework hooks (existing examples)

# Step 2: Generate patch with Qwen
echo "Create a bytecode patch for Creature.getCombatRating()
that fires a CombatRatingEvent before returning.
Follow the ItemDamagePatch pattern." > prompt.txt

qwen_smart_codegen.py prompt.txt --pattern bytecode_patches

# Step 3: Verify with combined index
python3 combined_index_query.py compare "CombatRating"
```

---

### Workflow 2: Bulk Patch Generation

**Goal:** Create patches for all combat methods

```bash
# Step 1: Find all combat methods in server
python3 combined_index_query.py search "combat"

# Step 2: List server methods to see targets
python3 combined_index_query.py server-methods | grep -i combat

# Step 3: Generate patches in bulk
for method in getCombatRating getDefenceRating attack defend; do
  echo "Create bytecode patch for Creature.$method" > prompt_$method.txt
  qwen_smart_codegen.py prompt_$method.txt --pattern bytecode_patches
done
```

---

### Workflow 3: Understanding Server Code

**Goal:** Understand how items work

```bash
# Find all item-related methods in server
python3 combined_index_query.py search "Item"

# See existing item hooks in framework
python3 combined_index_query.py framework-hooks | grep -i item

# Compare coverage
python3 combined_index_query.py compare "Item"
```

## 🤖 Integration with Qwen Automation

### Via MCP Endpoint

The `/qwen/generate` MCP endpoint can use **either index**:

```json
{
  "prompt": "Create ItemDamagePatch for Item.damage() method",
  "search_term": "ItemDamage",
  "dry_run": false
}
```

**Qwen automatically:**
1. Searches framework index for "ItemDamage" pattern
2. Searches server index for target method
3. Generates patch with smart context from both
4. Uses only ~100 tokens vs 10,000+

---

### Manual Qwen with Combined Context

```bash
# Extract context from both indexes
python3 combined_index_query.py compare "damage" > context.txt

# Generate with context
qwen_smart_codegen.py prompt.txt --search "ItemDamage"
```

1. **Server index is REFERENCE ONLY**
   - Never edit decompiled server code
   - Only use for understanding and finding patch targets

2. **Framework index is YOUR code**

   - Regenerate index after changes

   - Each can be queried independently
   - Combined tool queries both simultaneously

4. **MCP integration**
   - Both indexes available via MCP endpoints
   - Qwen endpoint uses framework index by default
